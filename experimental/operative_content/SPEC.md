# Generic Operative Content Construction — TEST_ONLY preregistration

Baseline: b155848bcd335453189d6ec0d6c426d4dedb4d5a.
Status: DEFINED before implementation/experiment. This file's criteria are frozen.

Question: can experience-formed S1, in one isolated ACore lifetime, become an
ordinary execution dependency of new typed content T1, persisted in authoritative
Current State and used again as construction material after process restart?

## Candidate operation and scope

Reuse the frozen TEST_ONLY operative engine's relation formation and traversal.
At its ordinary operand-read hook, before expected-outcome calculation, expose
every reached outcome as a typed UnitRef. Construct Pair(left, current UnitRef)
for every admitted left operand. Left operands are all reached UnitRefs and all
previously saved Pairs whose transitive UnitRef leaves belong to that reached set.
The current UnitRef is the ordinary interpreter's current_pattern produced from
the current ChangeSet. No result is chosen. This is a new, externally supplied,
fixed generic construction rule, not a universal recursion law or autonomous
operation selection. S0/S1 are interpreted identically; provenance is not read.

Content identity depends only on type and operands, not on UUID, version, evidence,
relation path or origin labels. Pair is an ordered product, not a relation trace:
it can be recursively evaluated into two operand values and nested as a later
constructor input. Stored content is immutable by convention with full validation
and detached copies at boundaries. No external supplied complete T1 is allowed.
All newly constructed Pair identities join the actual expected-outcome operand
set before ordinary partial calculation, and persist in l0_state.content_test_only.
There is no post-advance content attachment or specialized answer consumer.

Unit records plus all content nodes share the existing locked units cap. A whole
construction batch that does not fit is rejected before Core commit; no pruning,
partial selection, replacement or fallback. Existing caps are unchanged.

Only an explicit versioned experimental Core subclass may run this rule. It uses
the existing guarded operative Core lifecycle, with an additional content version
and DB/individual binding. Default and old operative Core reject content-mode DBs
before writes. FakeBridge forbids body calls; no sampler/binder/expression/perform.

## Frozen criteria (GC-T1–GC-T10)

1. GC-T1 ORIGIN: supplied S0 and later S1 use one interpreter and one constructor;
   no supplied T1, no edge-specific branch or privileged provenance.
2. GC-T2 FORMATION: S1 is absent at origin and forms from ordinary synthetic
   observations/experience/integration after startup under the frozen old rule.
3. GC-T3 CONSTRUCTION: a later ordinary ACore.accept_observation constructs typed
   Pair content using operands made accessible by S1. T1 is neither path trace,
   log attachment nor a copied field; it has evaluable product content.
4. GC-T4 PERSISTENCE: T1 and its references/supports occur in committed authoritative
   Current State, serialize exactly and restore in a new process, same DB/A.
5. GC-T5 REUSE: restored T1 is an actual left operand of a later constructor;
   a nested Pair containing its reference is produced, without reconstructing T1
   from audit history. The next carrier-gap round need not produce a partial.
6. GC-T6 CAUSALITY: same pre-read state/input, mask only S1; actual newly constructed
   content and actual expected operands differ. Reinsertion restores content.
7. GC-T7 NEUTRALITY: provenance removal/swapping and disconnected relation changes
   do not change construction. Consistent arbitrary identifier renaming preserves
   structure under the induced renaming, with no literal fixture identifiers used.
8. GC-T8 HISTORY/PLURALITY: different synthetic histories affect content, and all
   multiple eligible operands produce results, with no first/latest/rank selector.
9. GC-T9 SAFETY: malformed/missing refs/types, cycles, incompatible modes/versions,
   DB binding errors and capacity exhaustion reject without commit or fallback.
10. GC-T10 COMPATIBILITY: default Core and frozen sources/evidence unchanged in
    semantics; focused, related and full original Python regressions pass.

PASS requires all ten. FAIL: measured causal criterion contradicted or hidden
answer source. NOT_READY: no lawful implementation of construction in the ordinary
interpreter. NOT_TESTABLE: required verification environment/evidence unavailable.
No acceptance edits after results. Preserve every failed verification attempt.

## Controls and evidence

Paired S1-only masks stop at the normal Core commit boundary without changing the
canonical DB. Compare typed content values/references and expected operands, not
UUIDs or audit-only fields. Reinsertion uses the same checkpoint. Provenance and
disconnected operands are changed independently. Other controls: two different
histories; identifier-renamed states; multiple operands; insufficient capacity;
illegal/cyclic content; wrong mode/version/DB; old/default Core refusal; tripwires
for sampler, binder and body; content reuse through a genuine subprocess restart.
Fresh independent TEST_ONLY DBs only; no selected/mainline A or old DB is read.

## Nonclaims

No complete expression, action code authorship, parameter authorship, expression
adoption, body authority, autonomous goals, Minecraft behavior, L1 or universal
Perfect Recursion realization. This first content construction subproblem does
not replace the frozen outward-expression authorship question.
