# Occurrence-driven operative effects — TEST_ONLY candidate

This is a minimal attempt within the existing body-connection task, not a theory
law or a revision of any previous acceptance. Existing uncommitted files remain
unchanged. Preregistered before this implementation's first execution.

## Fixed candidate rule and authorship

An ordinary integration may form an EffectRoute when an existing exact binding
receiver→before and an actual numeric before→after change share the exact typed
before endpoint. The route retains the sensor namespace, channel, kind and exact
typed endpoints. Receiver identity comes from the binding, never from a fixture
port argument. All qualifying routes are retained. This is an externally provided
general formation hypothesis; endpoint content comes from synthetic experience.
It does not establish that the recorded action caused the observed change.

During a LATER ordinary operative read, only a fresh current change occurrence
matching the entire route trigger can activate it. The receiver and both value
endpoints must be accessible in that actual read. Mere saved routes, candidate
Pairs, current scalar equality, or audit/query results cannot activate effects.
The formation round cannot execute a newly formed route.

An activated route propagates the current occurrence's after operand to its
receiver. The same propagation rule permits internal cells and native parameter
slots. A cell write has no body side effect. A native slot's declared owner and
protocol label mechanically assemble arguments. All required arguments must be
present, valid and unambiguous. Missing parameters are never filled. A complete
native operation is constructed INSIDE the ordinary read hook. A Core mechanical
tail may reserve that committed operation, send its exact expression once, record
the receipt and leave subsequent observations to the same Core. No raw action
record supplies future expression contents.

Two body operations in one activation batch are not ordered by the host. The
whole physical batch is refused; conflicting parameter values are also refused.
Both saved slot=0/slot=1 candidates remain. Unique activation is a consequence of
the tested occurrence/route content, not removal of an unwanted candidate.

EF-T2: later current occurrence activates a persisted route in the ordinary read.
EF-T3: route-only ablation removes actual effect; restoration restores it.
EF-T4: no occurrence, wrong channel/type, missing support or unreachable endpoint
cannot activate; historical Pairs/queries alone cannot dispatch.

routes change concrete operation contents; rename/provenance/distractors do not
introduce a selector. Preserve both existing binding candidates.

invalid or ambiguous arguments and concurrent physical effects refuse without
defaults, ranking, first/min/latest/random selection or retry.

routes can reenter after process restart without historical replay.
EF-T8: the same occurrence propagation can write an internal typed cell; bodies
are one native effect interface, not the only possible structural effect.
EF-T9: reserve-before-transport, receipt correspondence and same-Core subsequent
input are verified offline; uncertainty never retries the reserved occurrence.
EF-T10: unchanged 64 shared Unit/content/effect-packet limit and 96 relation/route
limit, old file preservation and existing regressions remain valid.

Local PASS only establishes this candidate rule under synthetic experience and
FakeBridge. Overall PARTIAL requires local effect evidence, while real-world
authorship, consequences and sustained feedback remain unestablished. Overall
NOT_READY if the rule fails these causal boundaries. Real evidence requires real
current occurrences and matching real requests/receipts/renewed observations;
no synthetic receipt is relabeled as a real action. Minecraft is not started
unless such an eligible current activation can be obtained without external
action content, input alteration, history substitution or an alternate witness.

The runtime transport reservation is current-state material, not a second action
history. It retains at most one attempt. Earlier request/receipt evidence remains
in EventStore; monotonic state/frame checks prevent reviving an old occurrence.
For a live carrier check, the fixed window is at most eight fresh observations
over 30 seconds, one continuous fresh experimental DB/individual, no training
injection, no imported receipt and no forced input change. Zero eligible effects
means zero actions. Observation/transport/resource failure stops and preserves
the actual partial evidence; no retry or witness replacement is allowed.

No goal, reward, causal law, autonomous action selection, general expression
adoption, mainline adoption, L1 or universal recursion is claimed.
