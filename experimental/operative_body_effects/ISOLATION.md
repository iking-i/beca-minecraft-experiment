# Isolation and exact attribution

This package extends the current uncommitted ReferenceEngine/ReferenceCore through
subclasses. Their existing sources, frozen FormalL0 and prior reports are not
edited. No production Core import, launcher selection, existing database or
theory reference is changed. Only EffectCore with an explicit versioned config
uses this candidate law. Default ACore rejects this operative database. Fresh
creation refuses preformed effect routes; restart checks the same database,
individual and mechanism metadata before use. This is not a production migration.

`EffectEngine._form_operative_dependencies` runs in ordinary integration AFTER
the current read, so a new EffectRoute cannot execute in its formation round.
`_read_operative_operands` activates a previously formed route only on a fresh
matching current change and executed endpoint supports. It constructs receiver
effects and complete NativeOperation operands BEFORE FormalL0 computes the
normal expected_outcomes. Cell writes also happen there, in the working state;
failure/capacity rejection prevents publishing the transition.

`native.project` is declared-interface decoding. It cannot choose a receiver,
value or trigger. It reads only current effect packets, not historical Pairs.
The Core tail accepts no code/parameter/query argument, commits the ordinary
state, reserves its current operation before transport, and records exactly one
receipt/failure. Subsequent observations enter the same Core normally. Public
action entrypoints still refuse; tick has no sampler/binder stage.

The synthetic initial receipt's port and value are externally supplied experience
premises. They are NOT internally authored past behavior. The candidate generic
law is also external. In the successful control, the future value 1 is not copied
from receipt slot=0: it is carried by a current occurrence through a learned route.
The native code comes from that route's slot owner, originally learned from the
external premise. This establishes a local causal construction/activation result,
not autonomous tool choice or real-world causality.

The body is a native effect implementation, not a learned dispatch table. A
creator-supplied typed cell uses the same occurrence/receiver rule with no body
call. This does not require every functional branch to exist at initialization.

All body declarations stay in the complete interface register. Actual Units,
Pair nodes, cells and current effect/operation nodes share the unchanged 64 limit;
effect routes/bindings share 96 with existing relations/connections. No candidate
is removed to create uniqueness. Multiple conflicting activations or physical
operations produce no physical dispatch. This refusal supplies no chosen action
or host-authored execution order.

Real readiness is deliberately narrower than offline success. Existing real raw
observations do not automatically contain the synthetic typed receipt premise
accepted by ReferenceEngine. The bounded live entry injects neither that premise
nor synthetic frames; it may therefore observe no eligible action. No guessed
port, historical import, forced transition or demonstration action remedies this.
Numeric occurrence exactness and accumulating Pair construction also retain the
existing capacity limitations. No long-run or arbitrary-real-scene guarantee is
made.
