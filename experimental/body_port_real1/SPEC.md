# BPC-R1 — Real-Experience Body-Port Connection Formation

Pre-registered before formation/validation. Base: ebdcbc73d060ce894513f35853ed01c5d47836ef.
This is an independent TEST_ONLY stage; BPC-0 and all other frozen results remain unchanged.

## Question and scope

Can one recorded real Minecraft execution, through its real receipt, renewed
ObservationFrames and committed individual history, produce a supported C ↔ O
using generic shared-incidence formation? O is the native catalog version/code.
Only parameterless formal primitive capabilities, one unambiguously recorded
successful action per consecutive observed interval, and nonempty observed change
are eligible. Successful input transmission is not proof of a world-effect law.
No formed connection executes perform; no expression or execution consumer exists here.

## Input and source boundary

RealExperience preserves immutable canonical copies of EXPERIENCE_FORMED,
ACTION_REQUESTED, ACTION_EXECUTED (including entire receipt), both OBSERVATION_FRAME
and WORLD_OBSERVATION events, BODY_CAPABILITIES_PROVISIONED, and session environment.
All event identities, individual/session/version/sequence provenance are retained.
Source database opens mode=ro, query_only, with a single read transaction.
No EventStore, Core, bridge, Minecraft or worker is started.
The loader verifies recorded relationships, receipt code/parameters/status,
frame sequence/namespace/body epoch, native catalog identity, and encoder numeric
fidelity against the corresponding raw WORLD_OBSERVATION. It rejects missing,
mixed, ambiguous or inconsistent material instead of supplying defaults.

RealChange is an exact description of all recorded channel changes, including
appeared/disappeared/unobserved facts. Numeric identity preserves integer vs float
and exact finite float bits (hex); no rounding/epsilon. Scope includes individual,
encoding namespace, body epoch and native catalog version. Full frames remain
provenance roots; they are not converted into BPC-0 integer Samples.
Existing human-readable raw diagnostics are preserved only in opaque evidence
copies, never interpreted by formation or used as action/semantic selectors.

## Formation

Mechanical encoding derives C from verified before/after change material;
the actual execution record supplies O. It creates ordinary Member(experience,C)
and Member(experience,O) with direct supports, never a seed C ↔ O connection.
Reuse unchanged BPC-0 generic form(): same-group Member facts produce Shared.
Verification only reads formed facts/supports. It returns all supported native
ports; if cardinality exceeds one, status is AMBIGUOUS and no port is adopted.
No sampler/binder/perform is called; no expression is produced.

## Pre-registered acceptance

PASS requires a real eligible witness, supported Shared(C,O) absent in seed
material and formed by the unchanged generic rule; native O; exact provenance;
and all negative controls passing:
1. Remove necessary experience root: connection unsupported.
2. Remove O identity root: connection unsupported.
3. Remove necessary recorded change/frame material: connection unsupported.
4. Add disconnected distractor material: original supported connection unchanged.
5. More than one supported port: return AMBIGUOUS with all ports, never choose.
Also test input-level deletions are rejected/produce no formation; no execution
calls exist. Support screening does not rerun formation or alter canonical data.
FAIL means available valid material fails formation or any control/integrity check.
NOT_TESTABLE means required real material is absent/incompatible/unverifiable.
