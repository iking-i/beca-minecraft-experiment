## Candidate and attribution

The minimal supplemental experience representation is an externally supplied
**synthetic typed execution receipt**: catalog version, native code, execution
identity, executed status and explicit incidence `(slot_unit_ref, operand_unit_ref)`.
Both references must already be declared/observed native operands. It contains
no operative edge, future expression or adopted choice. Its original assignment
is external; this experiment does not validate this representation against real
Minecraft receipts or call perform. No field-name matching converts raw commands.

Ordinary integration registers receipt incidence as DirectedConnection(slot,value).
The existing TC law forms DirectedConnection(value_before,value_after).
The extension then applies one generic exact-endpoint composition step to a
snapshot of current edges: DirectedConnection(a,b), DirectedConnection(b,c)
produce DirectedConnection(a,c), if a is a ParameterSlot and b/c are ObservedValue.
All such supported compositions are retained. Type/range validation may reject
an invalid batch, but never supplies, selects or replaces an endpoint. No global
closure, cross product of compatible values, slot-name routing or ranking.

The same existing TC constructor consumes all admitted edges as UnitRef/Pair,
before ordinary partial computation. New receipt/derived edges first execute in
a later advance. Evidence is separate from execution. S0/S1 share interpretation.

The decisive **new** binding must not occur in any input receipt. Its slot comes
from receipt incidence; its new value comes from independently experienced
same-channel temporal change. This is structural candidate formation, not a
claim that changed sensor values are useful or correct future action parameters.
Reference assignments may be registered as observed premises, but propagation
to new reference values is not claimed by this first scalar composition law.
