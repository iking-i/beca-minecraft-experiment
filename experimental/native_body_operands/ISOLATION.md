# Isolation and attribution

NativeCore extends the existing ContentCore lifecycle, without editing that
frozen package. NativeEngine extends ContentEngine and reuses its advance and
the already validated ordinary operative interpreter. The input boundary creates
typed Unit records plus exact observation-Unit/input incidence; it creates no
operative dependency edge. S1 formation remains the unchanged old candidate law.

The sole production edit is two lines of read-only native-mode admission after
the established argument/cap preflights and before lease/schema/session writes.
Old/default Core cannot adopt a native-mode database; the explicit new Core cannot
silently convert an old database. This is an admission guard, not a default
execution change. No existing engine, body, policy, cap or database is changed.

The new read hook uses the original ordinary relation traversal, then exact
incidence from reached outcome Units to typed sensor Units. It copies the frozen
ContentEngine constructor block (UnitRefs, eligible saved Pair leaves, ordered
Pair(left,current UnitRef), whole-batch admission and actual expected operands)
with the same semantics. This avoids changing or broadening the frozen validator.
The additional input set is the only construction difference; there is no
code-specific branch or interpretation of Pair as an action. No after-advance
consumer/attachment creates products. No separate graph runtime supplies answers.

Typed NativePort is catalog version/code; ParameterSlot contains exact declared
port/name/domain refs and required status. ParameterDomain retains its entire
schema. ObservedValue is an exact observed scalar with numeric type, not a selected
parameter value. ObservedReference is a sensed token/kind/namespace/body-epoch,
not a promised current execution target. All appear as ordinary UnitRef operands
and can be nested using the same Pair operation. No domain endpoints are sampled
or converted into values. No parameter-slot/value binding or expression is formed.

All unique materials in an observed declaration/sensor sample are admitted
together; canonical identity shares exact duplicate values/domains. Provenance
is stored separately from executable incidence and does not grant permissions.
Input incidence is an externally supplied sensor representation law, not an
internally invented body relation. Experience-formed operative reachability
determines whether that material is actually used in the normal constructor.
The experiment's subset of observed ports is synthetic environmental input,
not a choice of output action; all supplied ports coexist without selection.

This uses frozen first-created Unit pattern identity. It does not pretend that
repeated channel/kind identities preserve every later scalar magnitude or ref
epoch. Restored historical reference material can remain a constructor input;
that does not establish it is valid for a future body action. Source snapshots
permit provenance validation, not full EventStore replay. Current State is the
restore authority, including when Full Audit History is OFF.

Units (including all new atoms) plus content nodes share the unchanged 64-unit
witness capacity; whole batches reject without pruning or alternative outputs.
The witness finishes with 16 Unit records and 47 content nodes (63/64), not an
unbounded-memory claim. No cap increase or future limit handling is implemented.

The uncommitted operative_expression SPEC/NOT_READY reports remain byte-identical
and outside this implementation commit, as do unrelated TEST_ONLY files.
CE-T1–CE-T10 are not changed or passed by this interface result. No complete
expression, action/parameter authorship, adoption, autonomous goal, body authority,
Minecraft execution, L1 or universal recursion is claimed.
